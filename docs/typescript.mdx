## Doel

TypeScript is JavaScript met ondersteuning voor types. Hierdoor kan TypeScript veel fouten vinden voordat je de applicatie uitvoert. Dit maakt grotere React- en Node.js-projecten beter leesbaar en eenvoudiger om aan te passen.

Na dit hoofdstuk kan je:

- uitleggen waarom we TypeScript gebruiken;
- types laten afleiden of zelf toevoegen;
- functies, arrays en objecten typen;
- interfaces en type aliases gebruiken;
- werken met union en literal types;
- generics en belangrijke utility types toepassen;
- een type veilig verkleinen met type guards;
- vermijden dat `any` de typecontrole uitschakelt.

<aside className="courseCallout courseCallout--warning">

<strong className="courseCallout__title">Geen `any`</strong>

We gebruiken nergens zelf `any`. Met `any` schakel je de typecontrole voor die waarde uit. Onnodig gebruik kan punten kosten bij de evaluatie.
</aside>

## Hoe werkt TypeScript?

Browsers en Node.js voeren JavaScript uit, geen TypeScript. De TypeScriptcompiler controleert de types en verwijdert daarna alle type-informatie. Het resultaat is gewone JavaScript.

TypeScript bestaat uit drie belangrijke onderdelen:

- **de taal**: JavaScript met extra syntax om types te beschrijven;
- **de compiler**: controleert de types en zet TypeScript om naar JavaScript;
- **de taaldienst**: geeft onder andere type-informatie, autocomplete en refactoring in VS Code.

## Type inference

TypeScript kan het type van een waarde meestal zelf afleiden. Dit noemen we **type inference**.

```typescript
const titel = "The Matrix";       // string
let speelduur = 136;              // number
const actief = true;              // boolean
const genres = ["actie", "sci-fi"]; // string[]
```

Bij een gewone `const`-variabele kan geen nieuwe waarde toegewezen worden. Voor het controleren van je code is `titel` hier bruikbaar als een `string`. Binnen een object worden properties standaard breder afgeleid, omdat hun waarde nog aangepast kan worden.

```typescript
const film = {
  titel: "The Matrix",
  speelduur: 136
};

film.titel = "Inception"; // Toegelaten: film.titel is van het type string.
```

<strong className="courseCallout__title">Bekijk het afgeleide type</strong>

Hover in VS Code over een variabele of functie om te zien welk type TypeScript heeft afgeleid.
</aside>

## Basistypes

### Primitieve types

De meest gebruikte primitieve types zijn `string`, `number` en `boolean`.

```typescript
const titel: string = "The Matrix";
const speelduur: number = 136;
const actief: boolean = true;
```

Wanneer TypeScript het juiste type al kan afleiden, hoef je dit niet opnieuw te schrijven. De expliciete types hierboven zijn dus niet noodzakelijk.

```typescript
const titel = "The Matrix";
const speelduur = 136;
const actief = true;
```

### Arrays

Plaats `[]` achter het type van één element om een array te typen.

```typescript
const genres: string[] = ["actie", "sciencefiction"];
const scores: number[] = [8, 9, 7];
```

De langere vorm `Array<string>` is ook geldig, maar in deze cursus gebruiken we meestal `string[]`.

### Tuples

Een tuple is een array met een vaste lengte waarbij iedere positie een eigen type heeft.

```typescript
const vertoning: [string, number] = ["20:30", 42];
```

Hier moet het eerste element een `string` zijn en het tweede een `number`.

### Union types

Met `|` geef je aan dat verschillende types of waarden toegelaten zijn.

```typescript
let geselecteerdeFilmId: number | null = null;

geselecteerdeFilmId = 2;
```

Een union met vaste waarden noemen we een **literal union**.

```typescript
type FilmStatus = "concept" | "actief" | "gearchiveerd";

const status: FilmStatus = "actief";
```

Een waarde zoals `"verwijderd"` is niet toegelaten, omdat ze niet in `FilmStatus` staat.

### `unknown` in plaats van `any`

Wanneer je het type echt nog niet kent, gebruik je `unknown`. Je moet dan eerst controleren wat de waarde is voordat je ermee werkt.

```typescript
const toonWaarde = (waarde: unknown): void => {
  if (typeof waarde === "string") {
    console.log(waarde.toUpperCase());
  }
};
```

Dit is veiliger dan `any`, omdat TypeScript je verplicht om de controle uit te voeren.

## Functies typen

Bij een functie kan je de parameters en de returnwaarde typen.

<AnnotatedCodeBlock>

```typescript
const berekenVrijePlaatsen = (capaciteit: number, verkocht: number): number => { // [!note Iedere parameter krijgt een type. Na de parameterlijst staat het type van de returnwaarde.]
  return capaciteit - verkocht;
};
```

</AnnotatedCodeBlock>

TypeScript kan de returnwaarde vaak zelf afleiden. Bij functies die deel uitmaken van de publieke werking van je applicatie kan een expliciet returntype wel extra duidelijkheid geven.

### `void`

Gebruik `void` wanneer een functie geen bruikbare waarde returnt.

```typescript
const logFilm = (titel: string): void => {
  console.log(titel);
};
```

### Optionele en standaardparameters

Een optionele parameter krijgt een `?`. Een standaardparameter krijgt een waarde met `=`.

<AnnotatedCodeBlock>

```typescript
const beschrijfFilm = (
  titel: string,
  taal = "Nederlands", // [!note TypeScript leidt hier automatisch het type string af.]
  ondertiteling?: string // [!note Door het vraagteken mag deze parameter ontbreken.]
): string => {
  return ondertiteling
    ? `${titel}: ${taal}, ondertiteld in ${ondertiteling}`
    : `${titel}: ${taal}`;
};
```

</AnnotatedCodeBlock>

Een verplichte parameter mag niet na een optionele parameter komen.

### Een functietype hergebruiken

Met een type alias kan je de volledige vorm van een functie beschrijven.

```typescript
type FilmFilter = (minimumLeeftijd: number) => boolean;

const geschiktVoorKinderen: FilmFilter = (minimumLeeftijd) => {
  return minimumLeeftijd <= 12;
};
```

## Objecten typen

### Interfaces

Een interface beschrijft de properties van een object.

```typescript
interface Film {
  id: number;
  titel: string;
  speelduur: number;
  genres: string[];
  actief: boolean;
}

const film: Film = {
  id: 1,
  titel: "The Matrix",
  speelduur: 136,
  genres: ["actie", "sciencefiction"],
  actief: true
};
```

Een optionele property krijgt een `?`.

```typescript
interface Film {
  beschrijving?: string;
}
```

Interfaces met dezelfde naam worden door TypeScript samengevoegd. Dit noemen we **declaration merging**. Gebruik dit bewust; verspreid één eigen interface niet onnodig over verschillende plaatsen.

### Interfaces uitbreiden

Met `extends` maak je een nieuwe interface op basis van een bestaande interface.

<AnnotatedCodeBlock>

```typescript
interface FilmMetBeschikbaarheid extends Film { // [!note FilmMetBeschikbaarheid bevat alle properties van Film en voegt er één toe.]
  vrijePlaatsen: number;
}
```

</AnnotatedCodeBlock>

### Type aliases

Een type alias kan eveneens een object beschrijven.

```typescript
type Vertoning = {
  id: number;
  filmId: number;
  tijdstip: string;
  vrijePlaatsen: number;
};
```

Type aliases kunnen daarnaast ook gebruikt worden voor unions, tuples en primitieve types.

```typescript
type Id = number | string;
type FilmStatus = "concept" | "actief" | "gearchiveerd";
type TijdstipMetZaal = [string, number];
```

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Interface of type?</strong>

Gebruik een interface wanneer je vooral de vorm van een object beschrijft en die eventueel wil uitbreiden. Gebruik een type alias voor unions, tuples en combinaties van types. Voor gewone objecten zijn beide mogelijkheden correct; wees vooral consistent.
</aside>

## Enums en literal unions

Een enum geeft namen aan een vaste set waarden.

```typescript
enum GebruikersRol {
  User = "USER",
  Admin = "ADMIN"
}

const rol: GebruikersRol = GebruikersRol.Admin;
```

Voor eenvoudige vaste keuzes is een literal union vaak voldoende en levert deze minder extra JavaScript op.

```typescript
type GebruikersRol = "user" | "admin";
```

Gebruik een enum dus alleen wanneer je de enum ook echt als waarde tijdens de uitvoering nodig hebt.

## Generics

Met een generic schrijf je herbruikbare code zonder de type-informatie te verliezen. De concrete typeparameter wordt pas bepaald wanneer de functie, interface of het type gebruikt wordt.

<AnnotatedCodeBlock>

```typescript
const eersteElement = <T,>(waarden: T[]): T | undefined => { // [!note T stelt het type van één element voor. De functie werkt daardoor met verschillende soorten arrays.]
  return waarden[0];
};

const eersteTitel = eersteElement(["The Matrix", "Inception"]);
const eersteScore = eersteElement([8, 9, 7]);
```

</AnnotatedCodeBlock>

TypeScript leidt `T` hier automatisch af. Je hoeft dus meestal niet `eersteElement<string>(...)` te schrijven.

### Generieke interfaces

Generics zijn nuttig voor datastructuren waarvan de inhoud kan verschillen.

```typescript
interface ApiResponse<T> {
  data: T;
  message: string;
}

const response: ApiResponse<Film[]> = {
  data: [],
  message: "Films opgehaald"
};
```

Dezelfde `ApiResponse` kan later ook een gebruiker, vertoning of ander type bevatten.

## Utility types

Utility types maken een nieuw type op basis van een bestaand type.

### `Partial<T>`

`Partial<T>` maakt alle properties optioneel. Dit is bijvoorbeeld bruikbaar voor een update waarbij niet elk veld gewijzigd wordt.

```typescript
type FilmUpdate = Partial<Film>;

const wijziging: FilmUpdate = {
  speelduur: 140
};
```

### `Readonly<T>`

`Readonly<T>` voorkomt dat properties via dit type opnieuw toegewezen worden.

```typescript
type ReadonlyFilm = Readonly<Film>;
```

<aside className="courseCallout courseCallout--warning">

<strong className="courseCallout__title">Niet diep readonly</strong>

`Readonly<T>` werkt alleen op het buitenste niveau. Een geneste array of een genest object wordt hierdoor niet automatisch volledig readonly.
</aside>

### `Pick<T, K>` en `Omit<T, K>`

`Pick` behoudt alleen de gekozen properties. `Omit` laat de gekozen properties weg.

```typescript
type FilmPreview = Pick<Film, "id" | "titel">;
type NieuweFilm = Omit<Film, "id">;
```

### `Record<K, T>`

`Record` beschrijft een object met een vaste set keys en één type voor de values.

```typescript
type FilmStatus = "concept" | "actief" | "gearchiveerd";

const statusLabels: Record<FilmStatus, string> = {
  concept: "Concept",
  actief: "Nu te zien",
  gearchiveerd: "Niet meer beschikbaar"
};
```

TypeScript controleert dat iedere status aanwezig is.

### `Required<T>`

`Required<T>` maakt alle optionele properties verplicht.

```typescript
type VolledigeFilm = Required<Film>;
```

### `ReturnType<T>` en `Awaited<T>`

`ReturnType` haalt het returntype van een functie op. Bij een async functie is dit een `Promise`. Met `Awaited` haal je het type uit die Promise.

```typescript
const haalFilmOp = async (id: number): Promise<Film> => {
  throw new Error(`Film ${id} nog niet geïmplementeerd`);
};

type HaalFilmOpResultaat = ReturnType<typeof haalFilmOp>; // Promise<Film>
type OpgehaaldeFilm = Awaited<HaalFilmOpResultaat>;      // Film
```

## Type narrowing en type guards

Wanneer een waarde verschillende types kan hebben, moet je eerst controleren met welk type je werkt. TypeScript verkleint daarna automatisch het mogelijke type. Dit noemen we **type narrowing**.

### `typeof`

Gebruik `typeof` voor primitieve types.

```typescript
const formatteerId = (id: number | string): string => {
  if (typeof id === "number") {
    return id.toString().padStart(4, "0");
  }

  return id.toUpperCase();
};
```

### De `in`-operator

Gebruik `in` om te controleren of een property in een object aanwezig is.

```typescript
interface OnlineBetaling {
  bedrag: number;
  paymentId: string;
}

interface Kassabetaling {
  bedrag: number;
  kassamedewerker: string;
}

type Betaling = OnlineBetaling | Kassabetaling;

const beschrijfBetaling = (betaling: Betaling): string => {
  if ("paymentId" in betaling) {
    return `Online betaling: ${betaling.paymentId}`;
  }

  return `Kassabetaling door ${betaling.kassamedewerker}`;
};
```

### Discriminated unions

Een gedeelde property met een vaste waarde maakt unions eenvoudig en veilig te controleren.

```typescript
type LaadResultaat =
  | { status: "loading" }
  | { status: "success"; films: Film[] }
  | { status: "error"; message: string };

const toonResultaat = (resultaat: LaadResultaat): string => {
  switch (resultaat.status) {
    case "loading":
      return "Films laden...";
    case "success":
      return `${resultaat.films.length} films gevonden`;
    case "error":
      return resultaat.message;
  }
};
```

TypeScript weet in iedere `case` welke properties beschikbaar zijn. Dit patroon zullen we later vaak gebruiken voor loading-, success- en errorstates.

### Eigen type guard

Met `waarde is Type` kan een functie aan TypeScript vertellen welk type na een controle overblijft.

```typescript
const isFilm = (waarde: unknown): waarde is Film => {
  if (typeof waarde !== "object" || waarde === null) {
    return false;
  }

  return "id" in waarde && "titel" in waarde;
};
```

Deze eenvoudige controle kijkt nog niet na of iedere property zelf het juiste type heeft. Voor uitgebreide validatie van externe data gebruiken we later eventueel een schema-library.

## Controlevragen

### Waarom hoeft een type niet altijd expliciet vermeld te worden?

<details>
<summary>Toon het antwoord</summary>

TypeScript kan het type meestal zelf afleiden uit de toegekende waarde. `const speelduur = 136` wordt daardoor automatisch als een getal behandeld.

</details>

### Waarom gebruiken we geen `any`?

<details>
<summary>Toon het antwoord</summary>

`any` schakelt de typecontrole voor die waarde uit. Foute properties en bewerkingen worden dan mogelijk pas tijdens het uitvoeren ontdekt. Gebruik `unknown` wanneer het type nog niet gekend is en controleer het eerst.

</details>

### Wat is het verschil tussen een array en een tuple?

<details>
<summary>Toon het antwoord</summary>

Een array bevat een aantal elementen van een bepaald type. Een tuple heeft een vaste lengte en kan per positie een ander type verwachten.

</details>

### Wat is het verschil tussen een optionele property en `string | undefined`?

<details>
<summary>Toon het antwoord</summary>

Een optionele property met `?` mag volledig ontbreken. Bij een verplichte property van het type `string | undefined` moet de property aanwezig zijn, maar haar waarde mag `undefined` zijn.

</details>

### Wanneer kies je een interface en wanneer een type alias?

<details>
<summary>Toon het antwoord</summary>

Gebruik meestal een interface om de vorm van een uitbreidbaar object te beschrijven. Gebruik een type alias voor unions, tuples en combinaties van types. Voor een gewone objectstructuur zijn beide geldig.

</details>

### Welk probleem lossen generics op?

<details>
<summary>Toon het antwoord</summary>

Met generics kan dezelfde functie of structuur met verschillende types werken terwijl TypeScript de concrete type-informatie behoudt. Je hebt daardoor geen `any` nodig.

</details>

### Wat is het verschil tussen `Pick` en `Omit`?

<details>
<summary>Toon het antwoord</summary>

`Pick` maakt een type met alleen de gekozen properties. `Omit` maakt een type met alle properties behalve de gekozen properties.

</details>

### Maakt `Readonly<T>` ook geneste objecten en arrays readonly?

<details>
<summary>Toon het antwoord</summary>

Nee. `Readonly<T>` werkt alleen op de properties van het buitenste niveau. Geneste objecten en arrays moet je afzonderlijk readonly maken wanneer dat nodig is.

</details>

### Wat doet type narrowing?

<details>
<summary>Toon het antwoord</summary>

Type narrowing verkleint de mogelijke types na een controle. Na `typeof waarde === "string"` weet TypeScript bijvoorbeeld dat `waarde` binnen dat blok een string is.

</details>

### Waarom is een discriminated union handig voor loading-, success- en errorstates?

<details>
<summary>Toon het antwoord</summary>

De gedeelde `status`-property bepaalt welke andere properties beschikbaar zijn. Bij `success` kan je veilig de data gebruiken en bij `error` de foutmelding, zonder properties te gebruiken die in die toestand niet bestaan.

</details>
