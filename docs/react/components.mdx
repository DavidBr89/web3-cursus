## Waar staan we in het verhaal?

Onze eerste bioscooppagina kan volledig in `App.tsx` geschreven worden. Zodra meerdere films dezelfde titel, afbeelding, genres en knop tonen, herhalen we echter dezelfde markup. Een wijziging aan het uitzicht van een filmkaart moet dan op verschillende plaatsen gebeuren.

Daarom beginnen we de applicatie op te delen. Een filmkaart wordt een `FilmCard`, de navigatie wordt een `Navigation` en een volledige lijst wordt een `FilmList`. Zo krijgt ieder herkenbaar deel van de interface één duidelijke plaats.

Die components vormen samen een **componentboom**. Een component kan andere components gebruiken en wordt dan hun **parent**. De gebruikte components zijn de **children** van die parent.

```text
App
├── Navigation
└── FilmList
    ├── FilmCard
    └── FilmCard
```

In deze boom geeft een parent gegevens via props door aan zijn children. Zo stroomt de data in één richting: van boven naar beneden. Verder in dit hoofdstuk bouwen we deze onderdelen stap voor stap op.

## Components

React applicaties zijn opgebouwd uit **components**. Een **component is een onderdeel van de user interface** (UI) dat zijn eigen logica en uiterlijk bevat. Een component kan zo klein zijn als een knop, maar ook zo groot als een volledige pagina. Components zijn dus bouwblokken voor onze applicatie die markup, CSS en JavaScript combineren. 

Een component is een JavaScript-functie die JSX teruggeeft. Er is een verschil tussen de **definitie** van een component en het **gebruiken** ervan:

```tsx
// Dit is de definitie van de component.
const MyButton = () => {
    return <button>Ik ben een knop!</button>;
}

// Met deze JSX gebruiken we de component.
const App = () => {
    return <MyButton />;
}
```

React-components beginnen steeds met een hoofdletter. Daardoor weet React dat `<MyButton />` naar onze eigen component verwijst. Een naam met een kleine letter, zoals `<button>`, wordt als een ingebouwd HTML-element behandeld.

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

Een nieuwe component schrijven we in deze cursus steeds in een apart bestand met de extensie `.tsx`. **De naam van een component schrijven we in PascalCase**.
</aside>

```tsx
const MyButton = () => {
    return (
        <button>Ik ben een knop!</button>
    );
}
```

<aside className="courseCallout courseCallout--tip">

<strong className="courseCallout__title">Tip</strong>

Om een nieuwe component aan te maken kunnen we gebruik maken van een snippet namelijk `rafce` en dan `TAB` die ons onmiddellijk een basis component geeft.
</aside>

![](/img/react/rafce.png)

Kleinere, herbruikbare components zetten we in deze cursus in de map `src/components`. Volledige pagina's krijgen later een eigen map. Merk op dat we PascalCase gebruiken voor de componentnaam en de extensie `.tsx` voor het bestand. Na de snippet krijgen we deze component terug:

```tsx
const MyButton = () => {
    return (
         <div>MyButton</div>
    );
}

export default MyButton;
```

Met de moderne JSX-transform hoef je `React` niet bovenaan ieder componentbestand te importeren. Je importeert wel de functies en types uit React die je zelf gebruikt, zoals later `useState` of `PropsWithChildren`.

Merk op dat een componentbestand meestal:

- `import`-statements kan hebben om code uit andere bestanden te gebruiken;
- een JavaScript-functie bevat die JSX teruggeeft;
- een `export`-statement bevat waarmee de component in andere bestanden gebruikt kan worden.

## Importeren en exporteren

De kracht van componenten zit in hun herbruikbaarheid: je kan componenten maken die opgebouwd zijn uit andere componenten. Naarmate je applicatie groeit en componenten in elkaar genest worden, is het belangrijk om deze op te splitsen in aparte bestanden.

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

**Binnen deze cursus verwachten we dat elke component in een afzonderlijk bestand wordt ondergebracht**. Dit zorgt voor een duidelijke structuur, betere leesbaarheid en herbruikbaarheid van code.
</aside>

Dit is een afspraak binnen de cursus en geen technische regel van React. Een stuk UI verdient vooral een eigen component wanneer het:

- op meerdere plaatsen terugkomt;
- een eigen, duidelijke verantwoordelijkheid heeft;
- zelfstandig kan veranderen;
- of de parent-component te groot en onleesbaar maakt.

Maak dus niet automatisch van iedere `div` een nieuwe component. Een componentgrens hoort de structuur van de interface duidelijker te maken.

Met `export` maken iets beschikbaar vanuit een bestand. Met `import` gebruiken we die code in een ander bestand. Het exporteren kan op twee manieren gebeuren nl. via een `default export` en via een `named export`.

### Default export

Wordt meestal gebruikt voor React components en gebruik je wanneer jouw bestand één hoofdonderdeel exporteert.

<AnnotatedCodeBlock>

```tsx
const MyButton = () => {
    return (
        <button>Test</button>
    );
}

export default MyButton;  // [!note Voor een default export gebruiken we `export default ...`]
```

</AnnotatedCodeBlock>

Het importeren in een ander bestand gebeurt dan als volgt:

<AnnotatedCodeBlock>

```tsx
import MyButton from './MyButton.tsx';  // [!note Importeren gebeurt via `import` statement maar onze naam is zonder accolades `{}`, geen destructuring dus. Je mag bij een default export, bij het importeren ook zelf de naam kiezen.]
```

</AnnotatedCodeBlock>


### Named export

Een named export wordt gebruikt wanneer je meerdere dingen wenst te exporteren uit een bestand. Meestal voor bestanden met helper functies in.

```typescript

export const som = (a: number, b: number) => {
  return a + b;
}

export const vermenigvuldig = (a: number, b: number) => {
  return a * b;
}

```

Het importeren in een ander bestand gebeurt dan als volgt:

<AnnotatedCodeBlock>

```typescript
import { som, vermenigvuldig } from "./utils.ts";  // [!note Hier worden wel `{}` gebruikt en dit om dat je eigenlijk destructured uit een object waarbij de naamgeving dus hier wel van belang is van wat je geëxporteerd hebt.]
```

</AnnotatedCodeBlock>

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

Default exports en named exports kunnen gecombineerd worden in één bestand.
</aside>

<aside className="courseCallout courseCallout--danger">

<strong className="courseCallout__title">Belangrijk</strong>

In het `return`-statement van een React-component geven we HTML-achtige syntax terug. Dit is geen HTML, maar JSX. Tijdens het bouwen van de applicatie wordt JSX omgezet naar JavaScript.
</aside>

## JSX

**JSX is een syntaxuitbreiding voor JavaScript waarmee je HTML-achtige markup kan schrijven binnen een JavaScript-bestand**. Er bestaan andere manieren om components te beschrijven, maar JSX is binnen React de gebruikelijkste manier.

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

**JSX lijkt sterk op HTML, maar wordt omgezet naar JavaScript.** Daardoor kunnen we de structuur van de UI en de JavaScript-waarden die erin voorkomen dicht bij elkaar schrijven.
</aside>

### Regels

**Eén root element retourneren**: Wanneer een component meerdere elementen teruggeeft, moeten deze omgeven worden door één enkel parent-element, dit kan je doen door middel van een `div` element of een `React.Fragment`.

<AnnotatedCodeBlock>

```tsx
<div>  // [!note Deze div moet rond de `h1`, `img` en de `p` elementen staan om één root element terug te geven.]
    <h1>Web 3</h1>
    <img src="https://tenor.com/nl/view/javascript-programming-gif-25800240" />
    <p>JavaScript</p>
</div>
```

</AnnotatedCodeBlock>

Dit kan ook wel opgelost worden met een fragment `<></>`. Of ook soms met een `React.Fragment` ik zal verder nog uitleggen waarom je dit ooit zou moeten schrijven. **Een fragment zorgt er voor dat jouw DOM tree niet vervuild wordt met extra `div`'s** die niet nodig zijn voor styling bijvoorbeeld.

```tsx
<>
    <h1>Web 3</h1>
    <img src="https://tenor.com/nl/view/javascript-programming-gif-25800240" />
    <p>JavaScript</p>
</>

// OF

<React.Fragment>
    <h1>Web 3</h1>
    <img src="https://tenor.com/nl/view/javascript-programming-gif-25800240" />
    <p>JavaScript</p>
</React.Fragment>
```

**Sluiten van alle tags**: In JSX moeten alle tags expliciet gesloten worden. Zelfsluitende tags zoals `<img>` moeten geschreven worden als `<img />`. HTML is vergevingsgezinder dan JSX op dit vlak.

```tsx
<>
    <img src="https://tenor.com/nl/view/javascript-programming-gif-25800240" />
    <ul>
        <li>Les 1: ES syntax</li>
        <li>Les 2: React</li>
    </ul>
</>
```

**Gebruik meestal camelCasing**: JSX wordt achter de schermen omgezet naar JavaScript. **Attributen worden daardoor properties van JS objecten**. Wanneer je deze attributen in jouw component wil gebruiken, moeten ze dus geldige JS-namen hebben. JS laat bijvoorbeeld geen variabelen toe met koppeltekens `-` in de naam en sommige woorden zijn gereserveerd, zoals `class`.

Daarom worden veel attributen in camelCase geschreven. Bijvoorbeeld `onClick` in plaats van `onclick`. Omdat `class` een gereserveerd keyword is in JS, gebruiken we in JSX `className`.

![](/img/react/casing.png)

```tsx
<img src="https://tenor.com/nl/view/javascript-programming-gif-25800240" className="photo" />
```

## JavaScript in JSX

JSX laat je toe om HTML-achtige markup binnen een JavaScript-bestand te schrijven. Soms wil je daarin een dynamische waarde tonen. **Met `{ }` voeg je een JavaScript-expressie toe aan JSX.** Een expressie is code die één waarde oplevert, zoals een variabele, een berekening of de returnwaarde van een functie.

```tsx
const person = {
    name: "John Doe",
    age: 20
};

const Profile = () => {
    return (
        <section>
            <h2>{person.name}</h2>
            <p>Volgend jaar is {person.age + 1} jaar oud.</p>
        </section>
    );
}
```

Statements zoals `if`, `for` en `const` leveren zelf geen waarde op en kunnen daarom niet rechtstreeks tussen de accolades staan. Je plaatst ze boven de `return`, of gebruikt in JSX een expressie zoals een ternary. Dat zien we verder bij conditioneel renderen.

```tsx
const Avatar = () => {
    const avatarImg = "https://tenor.com/nl/view/javascript-programming-gif-25800240";

    return <img src={avatarImg} className="photo" />
}

export default Avatar;
```

Je kan ook functies aanroepen in deze accolades om de return waarde te tonen bijvoorbeeld:

```tsx

const today = new Date();

const formatDate = (date: Date) => {
    return new Intl.DateTimeFormat("nl-BE", { weekday: 'long' }).format(date);
}

const TodoList = () => {
    
    return <h1>{ formatDate(today) }</h1>
}

export default TodoList;
```

### Renderen is UI berekenen

Wanneer React een component rendert, roept React de componentfunctie aan om te berekenen welke JSX op het scherm hoort te staan. Dezelfde props moeten daarom telkens hetzelfde resultaat opleveren. Wijzig geen props en voer tijdens het renderen geen acties uit zoals een request versturen of de DOM handmatig aanpassen. In de volgende hoofdstukken leren we hoe veranderingen en interacties wel worden verwerkt.

### Het gebruik van dubbele accolades

**Naast `string`, `number` en andere JS-expressies kan je in JSX ook objecten doorgeven**. Objecten worden in JS ook weergegeven door accolades. **Wanneer je dus een JS object wilt doorgeven in JSX, moet je het object daarom in een extra paar accolades plaatsen `{{ }}`**. Je kan dit ook zien bijvoorbeeld bij inline CSS in JSX.


```tsx

const TodoList = () => {
    
    return (
        <ul style={{ 
            backgroundColor: 'black',
            color: 'pink'
        }}>
            <li>Leren van React</li>
            <li>Leren van TypeScript</li>
        </ul>
    );
}

export default TodoList;
```

## Doorgeven van data via props

React components gebruiken **props** om met elkaar te communiceren. Elke parent-component kan informatie/data doorgeven aan zijn **child-components** door hen props mee te geven. Props lijken op HTML-attributen, maar je kan **eender welke JS-waarde mee doorgeven, zoals objecten, arrays maar ook functies**.

Props zorgen voor een gegevensstroom van boven naar beneden:

```text
Profile (parent)
└── Avatar (child)
    ├── person
    └── size
```

`Profile` bepaalt in dit voorbeeld de waarden. `Avatar` ontvangt ze en gebruikt ze om de juiste afbeelding te beschrijven.

<aside className="courseCallout courseCallout--warning">

<strong className="courseCallout__title">Props stromen maar in één richting</strong>

Een parent kan props doorgeven aan een child, maar een child kan geen props terugsturen naar zijn parent. Daarom spreken we over een **eenrichtingsgegevensstroom**: van parent naar child. Een child kan later wel een functie oproepen die de parent via een prop heeft doorgegeven. Die functie kan vervolgens de state van de parent aanpassen.
</aside>

```text
Profile (parent)
    │
    │ person en size via props
    ▼
Avatar (child)
```

Wanneer meerdere components dezelfde veranderende waarde nodig hebben, plaatsen we die state meestal in hun dichtstbijzijnde gemeenschappelijke parent. Dit noemen we **state liften**. We werken dit uit in het hoofdstuk over [state](./state#state-liften).

### Stap 1: Props doorgeven aan een child component

We gaan props (data) doorgeven aan een component. In het onderstaande voorbeeld geven we twee props door namelijk een object (person) en een number (size).

```tsx

const Profile = () => {
    
    return (
        <Avatar 
            person={{ name: "John Doe", imageId: "1bX5QH6" }}
            size={100}
         />
    );
}

export default Profile;
```

### Stap 2: Props lezen uit de child component

Props kan je in de child-component uitlezen via het `props`-object tussen de haakjes van de componentfunctie. Iedere React-component ontvangt zo'n object. Wanneer een component geen props nodig heeft, hoeven we geen parameter te schrijven.


<AnnotatedCodeBlock>

```tsx
  // [!note Props moeten altijd getypt worden door middel van een interface of een type alias. Vergeet dit niet!]
interface AvatarProps {
    person: { name: string;
              imageId: string;
            };
    size: number;
}

const Avatar = (props: AvatarProps) => {  // [!note Hier komen altijd de props mee binnen in de React component, tussen de haakjes van de functie.]

    const { person, size } = props; // Destructuring
    
    return (
        <img
          className="avatar"
          src={getImageUrl(person)}
          alt={person.name}
          width={size}
          height={size}
    />
    );
}

export default Avatar;
```

</AnnotatedCodeBlock>

<aside className="courseCallout courseCallout--tip">

<strong className="courseCallout__title">Tip</strong>

De destructuring die hier gebeurde, kan ook rechtstreeks tussen de haakjes gedaan worden je hoeft dit niet altijd op een aparte lijn code te plaatsen. Meestal doe ik dit als er bijvoorbeeld maar 2 of 3 properties in zitten die ik wens te gebruiken.
</aside>

Je kan props zien als instelknoppen die je kan aanpassen. Ze vervullen dezelfde rol als argumenten bij functies, en eigenlijk zijn props ook het enige argument dat een component ontvangt. **React component functies krijgen dus altijd één argument mee binnen: nl. een props-object**.

#### Default waarde aan props

Je kan ook een **default waarde meegeven voor de props als deze niet doorgegeven werd door de parent component**.

<AnnotatedCodeBlock>

```tsx

interface AvatarProps {
    person: { name: string;
              imageId: string;
            };
    size?: number;  // [!note Hier heb ik de size prop optioneel gemaakt in de typing zodanig dat TS niet klaagt in mijn component dat deze prop verplicht is.]
}

const Avatar = ({ person, size = 100 }: AvatarProps) => {  // [!note Een default waarde kan je meegeven door middel van een `=` waarde te geven.]

    return (
        <img
          className="avatar"
          src={getImageUrl(person)}
          alt={person.name}
          width={size}
          height={size}
    />
    );
}

export default Avatar;
```

</AnnotatedCodeBlock>

<strong className="courseCallout__title">Tip</strong>

Door eerst de props in de component te typen waarin je deze binnenkrijgt, kan TypeScript je helpen met te vertellen welke props eventueel verplicht zijn en welke optioneel zodanig dat je ook geen fouten typt en de juiste waarde meegeeft.
</aside>

#### Forwarden van props

Soms kan het doorgeven van props repetitief worden daardoor kan je ook de props doorgeven met de spread syntax.

```tsx

interface ProfileProps {
    person: { name: string;
              imageId: string;
            };
    size: number;
    isSepia: boolean
}

const Profile = ({ person, size, isSepia }: ProfileProps) => {

    return (
        <div className="card">
            <Avatar
                person={person}
                size={size}
                isSepia={isSepia}
             />
        </div>
    );
}

export default Profile;
```

In bepaalde situaties kan het handiger zijn om niet altijd opnieuw deze props volledig te moeten schrijven en kan je gebruik maken van de spread operator om de props "uit te spreiden".

```tsx
interface ProfileProps {
```

#### JSX doorgeven als children

Het is gebruikelijk in HTML om tags te nesten.

```html
<div>
    <img />
</div>
```

Soms wil je dit ook met je eigen components kunnen doen deze nesten.

```tsx
<Card>
    <Avatar />
</Card>
```

Wanneer je dit op deze manier doet, **ontvangt de parent component deze inhoud via een prop genaamd `children`**. In het voorbeeld hierboven ontvant dus de Card component een children prop met de waarde een Avatar component.

<aside className="courseCallout courseCallout--warning">

<strong className="courseCallout__title">Let op</strong>

Type de `children` prop nooit manueel maar gebruik een ingebouwde type in React die we kunnen gebruiken namelijk de `PropsWithChildren`.
</aside>

<AnnotatedCodeBlock>

```tsx

import { type PropsWithChildren } from 'react';

const Card = (props: PropsWithChildren) => {
    return (
        <div className="card">
            {props.children}  // [!note Dit is een krachtig instrument waarmee we alle children kunnen gebruiken in onze eigen component.]
        </div>
    )
}

const Profile = () => {
    return (
        <Card>
            <Avatar person={{ name: "Jane Doe", imageId: "denf2"}} size={100} />
        </Card>
    )
}
```

</AnnotatedCodeBlock>

**Je kan een component met `children` prop zien als een component met een "opening" die door de parent component kan worden opgevuld met willekeurige JSX**.

</aside>

## Conditioneel renderen

**Components kunnen soms iets anders tonen gebaseerd op specifieke condities, dit noemen we conditioneel renderen**. In React kunnen we conditioneel renderen door middel van `if` statements, `&&` en `?:` operators.

```tsx

interface ItemProps {
    name: string;
    isPacked: boolean;
}

const Item = ({name, isPacked}: ItemProps) => {
    return <li className="item">{ name }</li>;
}

const PackingList = () => {
    return (
        <div>
            <ul>
                <Item isPacked={true} name="Space Suit" />
                <Item isPacked={false} name="Helmet with a golden leaf" />
                <Item isPacked={true} name="Photo of Jane" />
            </ul>
        </div>
    )
}
```

In het bovenstaande voorbeeld hebben we `Item` components met een `isPacked` prop waarbij true/false meegegeven werd. Als het true is willen we bijvoorbeeld een vinkje (V) zetten achter de naam. We kunnen dit doen met een if/else statement

```tsx
interface ItemProps {
    name: string;
    isPacked: boolean;
}

const Item = ({name, isPacked}: ItemProps) => {

    if(isPacked) {
        return <li className="item">{ name } V</li>;
    }
    
    return <li className="item">{ name }</li>; 
}
```

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

**Je kan een `if/else`-statement gebruiken in de body van een component, maar niet rechtstreeks tussen de accolades in JSX.** Een `if/else` is een statement en levert niet zelf één waarde op.
</aside>

### Conditioneel niets renderen met `null`

Soms wil je helemaal niets renderen. Stel dat je van het bovenstaande voorbeeld de ingepakte items niet wens te tonen. Een React component moet altijd iets teruggeven, in dit geval kan je `null` returnen om niets te renderen.

```tsx
interface ItemProps {
    name: string;
    isPacked: boolean;
}

const Item = ({name, isPacked}: ItemProps) => {

    if(isPacked) {
        return null;
    }
    
    return <li className="item">{ name }</li>; 
}
```

### Conditioneel renderen in JSX

#### De ternary operator `? :`

Bij het vorige voorbeeld zag het statement dat we returnde er grotendeels hetzelfde uit buiten het vinkje (V) dat er bij geplaatst werd. Dit is onhandig om repetitieve code te gebruiken. We kunnen ook conditioneel het vinkje (V) er bij zetten inline in de JSX. We kunnen dit doen met de ternary operator `? :`

```tsx
interface ItemProps {
    name: string;
    isPacked: boolean;
}

const Item = ({name, isPacked}: ItemProps) => {
    
    return <li className="item">{ isPacked ? name + " V" : name}</li>; 
}
```

<aside className="courseCallout courseCallout--tip">

<strong className="courseCallout__title">Tip</strong>

**De ternary operator is handig voor eenvoudige voorwaarden, maar gebruik hem niet overal of teveel. Wanneer de JSX te complex wordt is het beter om aparte components te maken, variabelen te gebruiken en/of de logica op te splitsen.**
</aside>

#### De AND operator `&&`

Een andere veelgebruikte verkorte syntax is de AND `&&` operator. **Binnen React wordt deze vaak gebruikt wanneer je alleen JSX wil renderen als een bepaalde conditie waar is, en niets wil renderen als de conditie onwaar is**.

```tsx
interface ItemProps {
    name: string;
    isPacked: boolean;
}

const Item = ({name, isPacked}: ItemProps) => {
    
    return <li className="item">{name} { isPacked && " V"}</li>; 
}
```

<aside className="courseCallout courseCallout--danger">

<strong className="courseCallout__title">Belangrijk</strong>

**Gebruik geen numbers aan de linkerzijde van de `&&`. Om de expressie te evalueren zet JS de linkerzijde automatisch om naar een boolean**. Wanneer de linkerzijde echter 0 is, krijgt de volledige expressie die waarde, en React zal dan effectief 0 renderen in plaats van niets. De oplossing hierbij is om de linkerzijde expliciet een boolean van te maken.
</aside>

## Renderen van lijsten

Vaak willen we meerdere gelijkaardige componenten weergeven op basis van een lijst van data. Hiervoor kunnen we de JS array methodes gebruiken om een array van data om te zetten naar een array van componenten (JSX).

```tsx

const persons = [
  'Creola Katherine Johnson: mathematician',
  'Mario José Molina-Pasquel Henríquez: chemist',
  'Mohammad Abdus Salam: physicist',
  'Percy Lavon Julian: chemist',
  'Subrahmanyan Chandrasekhar: astrophysicist'
];

const List = () => {
    
    return (
        <ul>
            {persons.map( p => {
                return <li>{ p }</li>
            })}
        </ul>
    );
}

```

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

We gebruiken de `map` methode omdat we eigenlijk onze data willen transformeren van bvb. een array van strings naar een array van JSX elementen. Als we een array meegeven in JSX worden alle elementen na elkaar gerenderd, daarom werkt dit.
</aside>

<AnnotatedCodeBlock>

```tsx

const numbers = [1, 2, 3, 4];
const listItems = numbers.map(n => <li>{ n }</li>);

  // [!note Het gaat dus eigenlijk over het transformeren van data.]
// Wordt eigenlijk het volgende [<li>1</li>, <li>2</li>, <li>3</li>, <li>4</li>]
```

</AnnotatedCodeBlock>

Als je nu in de console van de browser kijkt, krijg je een foutmelding. **Wanneer we met `map()` JSX maken, moeten we een speciale `key`-prop meegeven aan het bovenste JSX-element dat iedere iteratie teruggeeft**.

![](/img/react/key.png)

Meestal gaat onze data wel gestructureerder zijn dan de array van strings en gaat dit een array van objecten zijn (bvb. data dat van een API komt).


We krijgen nog steeds de fout in de console over dat elke child een unieke key moet hebben.

<aside className="courseCallout courseCallout--note">

<strong className="courseCallout__title">Opmerking</strong>

**Het bovenste JSX-element dat rechtstreeks door iedere iteratie van `map()` wordt teruggegeven, moet een `key`-prop hebben**.
</aside>

Keys laten weten aan React welk element uit een array overeenkomt met welke component, zodat React deze later kan herkennen. Dit wordt belangrijk wanneer elementen in een array kunnen veranderen van plaats, toegevoegd of verwijderd worden. 

Een key moet uniek zijn tussen de elementen in **dezelfde lijst**. De waarde hoeft dus niet uniek te zijn binnen de volledige applicatie. React gebruikt `key` zelf: een component ontvangt deze waarde niet tussen zijn gewone props. Heeft de component het id ook nodig, dan geef je het afzonderlijk door:

```tsx
<Person key={person.id} personId={person.id} name={person.name} />
```

<aside className="courseCallout courseCallout--tip">

<strong className="courseCallout__title">Tip</strong>

**We gebruiken als `key` prop steeds een echte unieke waarde waar mogelijk, als je een array van objecten krijgt heb je meestal een id property die de perfecte kandidaat is voor de waarden van een key**.
</aside>

```tsx
  profession: 'chemist',

  profession: 'astrophysicist',

    return (
        <ul>
            {people.map(p => (
                <li key={p.id}>{ p.name }</li>  // [!note Nu met een unieke `key` prop meegegeven.]
                )
            )}
        </ul>
    );
}
```

</AnnotatedCodeBlock>

<aside className="courseCallout courseCallout--danger">

<strong className="courseCallout__title">Belangrijk</strong>

**Gebruik zo weinig mogelijk of zelfs niet de index van een element in de array als `key`. Dit is niet aan te raden omdat de volgorde van elementen kan wijzigen wanneer items toegevoegd worden, verwijderd of herschikt**. Het gebruiken van een index als `key` kan hierdoor leiden tot moeilijk te vinden bugs. **Genereer ook geen dynamische `keys`** met bijvoorbeeld `Math.random()`, in dit geval zullen de keys steeds veranderen bij elke render waardoor React alle componenten en DOM-elementen telkens opnieuw moet aanmaken, dit zorgt voor een tragere applicatie. Gebruik daarom altijd een **stabiele en unieke identifier uit je data als `key`**.
</aside>

### Een lijst filteren

Soms willen we niet alle gegevens tonen. Met `filter()` selecteren we eerst de gewenste personen. Daarna zet `map()` die gegevens om naar JSX. Beide methodes maken een nieuwe array en wijzigen `people` niet.

```tsx
const chemists = people.filter(person => person.profession === 'chemist');

const ChemistList = () => {
    return (
        <ul>
            {chemists.map(person => (
                <li key={person.id}>{person.name}</li>
            ))}
        </ul>
    );
}
```

### Een lege lijst opvangen

Een lege array veroorzaakt geen fout: `map()` geeft opnieuw een lege array terug en React toont geen lijstitems. Voor de gebruiker is een duidelijke melding meestal beter. We combineren hier conditioneel renderen met het renderen van een lijst:

```tsx
interface PersonListProps {
    people: {
        id: number;
        name: string;
        profession: string;
    }[];
}

const PersonList = ({ people }: PersonListProps) => {
    if (people.length === 0) {
        return <p>Geen personen gevonden.</p>;
    }

    return (
        <ul>
            {people.map(person => (
                <li key={person.id}>{person.name}</li>
            ))}
        </ul>
    );
}
```

Dit voorbeeld toont de volledige gegevensstroom: de parent geeft de array door via de `people`-prop, `PersonList` kiest bij een lege array een andere UI en `map()` maakt voor iedere persoon een lijstitem met een stabiele key.

### Compositie met `children`

Maak een herbruikbare `Panel`-component die via `children` zowel een korte melding als een lijst kan omringen. Type de props in een `.tsx`-bestand met `PropsWithChildren`.

<details>
<summary>Toon een mogelijke oplossing</summary>

```tsx
import type { PropsWithChildren } from 'react';

interface PanelProps {
    title: string;
}

const Panel = ({ title, children }: PropsWithChildren<PanelProps>) => {
    return (
        <section className="panel">
            <h2>{title}</h2>
            {children}
        </section>
    );
}
```

De parent bepaalt de inhoud tussen `<Panel>` en `</Panel>`. `Panel` bepaalt alleen de gemeenschappelijke omlijsting.

</details>

## Check jezelf

### Wat is het verschil tussen een componentdefinitie en een componentinstantie?

<details>
<summary>Toon het antwoord</summary>

De definitie is de functie die beschrijft welke JSX de component teruggeeft. Met JSX zoals `<ProfileBadge />` gebruikt de parent die definitie en maakt hij een instantie in de renderboom.

</details>

### Waarom moet de naam van een eigen component met een hoofdletter beginnen?

<details>
<summary>Toon het antwoord</summary>

React behandelt een JSX-naam met een kleine letter als een ingebouwd HTML-element. Een hoofdletter vertelt React dat de naam naar een eigen componentfunctie verwijst.

</details>

### In welke richting stromen props?

<details>
<summary>Toon het antwoord</summary>

Props stromen van een parent naar zijn children. Een child wijzigt ontvangen props niet en stuurt geen props terug omhoog. Een parent kan wel een callbackprop doorgeven die de child na een interactie oproept.

</details>

### Waarom mag een component zijn props niet wijzigen?

<details>
<summary>Toon het antwoord</summary>

Props zijn read-only snapshots die door de parent werden bepaald. Door ze niet te muteren blijft de component voorspelbaar: dezelfde props leveren dezelfde JSX op.

</details>

### Wanneer maak je van een stuk UI een aparte component?

<details>
<summary>Toon het antwoord</summary>

Dat is zinvol wanneer het stuk UI herhaald wordt, een eigen verantwoordelijkheid heeft, zelfstandig verandert of de parent onleesbaar maakt. Niet iedere `div` heeft een eigen component nodig.

</details>

### Waarom kan een `if`-statement niet rechtstreeks tussen JSX-accolades staan?

<details>
<summary>Toon het antwoord</summary>

Tussen JSX-accolades verwacht React een expressie die één waarde oplevert. Een `if` is een statement. Je kan de `if` boven de `return` plaatsen of in eenvoudige JSX een ternary gebruiken.

</details>

### Wanneer gebruik je `&&` en wanneer een ternary?

<details>
<summary>Toon het antwoord</summary>

Gebruik `&&` wanneer je iets alleen bij een ware conditie wil tonen. Gebruik een ternary wanneer zowel de ware als de onware toestand elk andere output moeten tonen.

</details>

### Waarom heeft ieder rechtstreeks element uit `map()` een key nodig?

<details>
<summary>Toon het antwoord</summary>

De key geeft een item een stabiele identiteit binnen zijn lijst. React kan daardoor herkennen welk item werd toegevoegd, verwijderd of verplaatst en de juiste bestaande component en DOM-node behouden.

</details>

### Waarom zijn een array-index en `Math.random()` meestal slechte keys?

<details>
<summary>Toon het antwoord</summary>

Een index kan na invoegen, verwijderen of herschikken naar een ander item verwijzen. `Math.random()` maakt bij iedere render een nieuwe key. Beide verbreken de stabiele identiteit waarop React rekent.

</details>

### Ontvangt een component zijn `key` als gewone prop?

<details>
<summary>Toon het antwoord</summary>

Nee. React gebruikt `key` zelf. Als een child hetzelfde id nodig heeft, moet de parent het afzonderlijk doorgeven, bijvoorbeeld met `<Person key={person.id} personId={person.id} />`.

</details>
